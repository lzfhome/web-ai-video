# poetry · Agent 规则

> 本文件是 poetry 产线的 Agent 入口（原名 `README.md`）。  
> 做 poetry 前：先读本文件 → [`TEMPLATE.md`](TEMPLATE.md)（硬规则）→ [`SOURCES.md`](SOURCES.md)（选句与热度源）。

一句话：**书封就是画面，文字是代码排的，BGM 是你选的。**

> 有配音的版本用 `line/poetry-tts/`；版式一样，时长由配音决定。

## 给 Agent 看的

先读 [`TEMPLATE.md`](TEMPLATE.md)。里面是完整的输入格式、marks 规则、封面策略和验收清单。

选中心句之前先读 [`SOURCES.md`](SOURCES.md)：渠道、指标、登录方式、硬规则都在那一页。

## 选句红线（先看）

1. **先写一句主线，再选句**。每场都要服务这条主线，不能只戳情绪。
2. **感情类最多 50%**：感情类**只指爱情/romance**（爱情、CP、告白、思念、吃醋、虐恋），按场次计，台词 + 旁白合计。**其余内容全部按主线判断**，兄弟情、亲情、家国、战斗、命运、成长、幽默都不计入感情比例。
   - 6 场最多 3 场；7 场最多 3 场；8 场最多 4 场；5 场最多 2 场。
   - 50% 是上限，不是目标。
3. 其余 50% 给：主线、世界观、群像、战斗、命运、成长、幽默、时代背景。
4. 每场在 `context` 开头标 `[主线] / [感情] / [世界观] / [群像] / [其他]`；notes 汇总比例，交付前核对感情类 ≤ 50%。
5. **旁白 ≤50%**：按场次计，旁白最多一半，其余给台词；旁白和感情比例是两套账，不能互相抵扣。
6. **单卡 / 多卡按场景分**：`cards` 只有 1 张 → 旧单句模式（逐字/逐行、署名延迟）；2 张及以上 → 多卡模式（整块淡入淡出）。同一支片可以“旧 / 新 / 旧”混用，不是全片一个模式。
7. **每册卡数不固定**：按该册实际有多少合格热点句来定，可能 1 张、3 张、5 张；不要求各册拉平，没有热点就少做/不做，**不要用弱句凑数**。单册建议 1–6 张。`card_fade` 只作用于 2 张以上的场景。**主角全片卡片占比 ≤30%**（主角卡 ÷ 全片总卡，旁白+台词都算总数），配角、群像、旁白要占 ≥70%；多主角按每个主角分别算。
8. **台词/旁白交错**：只看连续性，不规定开头；按全片卡片顺序，**同类型连续最多 2 张**，不能 3 张以上连续旁白或连续台词。可以从台词开始，也可以从旁白开始。**单卡场景算 1 张，多卡场景每张都算；场与场之间不重新计数。**
9. **极端情况才让中心句压过顺序**：
   - 默认先守规则；不要因为某句更好就自动改顺序、卡数或单/多卡结构。
   - 多个好句，或好句与规则冲突：先列候选和方案让用户选，不要替用户定。
   - 只有用户确认“没有合规解”或明确授权时，才按中心句走；这时顺序可以完全不管。
   - 硬规则不能让：原文不改、不跨册、不编热度、不用弱句凑数。
10. **章节无法确认就不写章节**：`source` 可以留空，只保留册名/册号；但必须能确认这句在该册内，并在 `context`/notes 标“仅册级核对”。不能为了好看编一个章节。
11. **一个项目只用一个文本源**：句子、章名同源；平台热度只用于选句。定稿源没有章名就留空，不跨版补；两版有差异先列给用户选。
12. **定稿 ≠ work.json ≠ 成片**：selection md 是定稿记录，work.json 才是渲染输入；删掉 `deliveries/` 后项目回到 work.json 状态。更新已有项目不要反复 `build --name <同名>`，会生成 `-v2/-v3`；用 `compose.py` 覆盖 canonical 的 `poem.json`。

## 开题流程（先候选，后确认）

1. 先按册列候选中心句：原文、人物/旁白、章节、热度、类型；尽量列全。
2. 给出每册 1 卡/多卡、卡数、全片顺序的建议，可给 2–3 个方案。
3. 用可点击选项让用户选：中心句、单卡/多卡、卡数、顺序。
4. 用户确认后再写最终 `work.json`、compose、render；没确认不渲染。
5. 只有用户确认“规则内无解”时，才启用第 9 条的极端情况。

## 怎么用

```bash
# 0. 先查读者实际划得最多的句子
python workspaces/vibe-knowledge/line/poetry/tools/weread_hot.py "书名" --top 30

# 1. 从空白模板开始
copy workspaces\vibe-knowledge\line\poetry\build.skeleton.json  <你的 work.json>

# 2. 合成 + 建项目 + 渲染
python project.py build poetry --work <work.json> --name <slug>

# 3. 只合成，不建项目
python workspaces\vibe-knowledge\line\poetry\compose.py <work.json> <out.json>
```

产物：

```text
projects/<slug>/
├── project.json          # line: poetry
├── lessons/<slug>/

│   ├── assets/           # 封面、BGM
```

交付时 `deliveries/<date>_<slug>/` 必须同时有 `video.mp4`、`cover.jpg`、`post.txt`（B 站投稿包：标题候选/简介/标签/分区/封面说明/AI 声明）；只出视频不算交付。

作品目录**没有** `film.js`、没有引擎代码；入口在 `workspaces/vibe-knowledge/line/poetry/film.js`。

## 固定观感

| 项 | 值 |
|---|---|
| 书封 | 430×606，-1.8°，2px 黑边 + 1.5px 高光 |
| 字体 | 楷体。1–4 行自动 70/58/52/46px，5 行 42px；**6–7 行必须手写 `type_size: 44` 或 42** |
| 行数 | **单场最多 7 行；行内断句只能在标点后**，整句最后一行可以没有标点，不把一个句子切开 |
| 多行 | 一行一行出，2.3s/行，淡入 1.0s |
| 单行 | 0.4s/字，淡入 0.45s |
| 署名 | 末字后 2.0s；台词 `——人物`，旁白不署名 |
| 章节 | 署名下方一行，18 号；“第X章 章名”，**不写“X卷”** |
| 底部 | 封面 / 说明 / 作者 / 生平 四行；文字块不得压到这四行 |
| 停留 | 署名后 5–8s（按句长缩放）；最后一场固定 12s |
| BGM | -13dB，淡入 2s，淡出 6s；源曲前奏长时用 `bgm_from` 裁到 1.2s 静音，`bgm_fade_in` 控制淡入 |
| 转场 | 0.95s 黑场 |

## 底部四行（固定）

- 每张卡底部固定四行：

```text
封面：第X册 册名 · 出版社
说明：句子取自电子书版，与封面非同一版本，无册次对应关系；封面仅作展示，原文已核。
作者：作者名
生平：一句话作者小传
```

- **封面与中心句解耦**：封面只作展示，不要求中心句出自该册；句子按故事顺序排，封面按册序播。
- **册名只写封面上真实有的名字**；封面没有册名就不编，直接写 `第X册`。
- **编号按封面来，有册写册，有卷写卷**：封面是 `第X册` 就写 `第X册`，封面是 `卷X` 就写 `卷X`；用字跟封面一致（`卷壹` 不要写成 `卷一`），不要换算成全书连续册号。
- **多部作品合在一个片子里，各自从第 1 册 / 卷壹重新编号**，不要写成 1–17。
- 例：`封面：第1册 天机卷 · 团结出版社`、`封面：第1册 · 重庆出版社`、`封面：卷贰 东岛门人 · 长江出版社`。


BGM 前奏长时，先跑 `python cine/audio/tools/bgm_lead.py <音频> --keep 1.2`，按输出写 `bgm_from` / `bgm_fade_in`；**是裁剪，不是补静音**。详见 `TEMPLATE.md` 的「BGM 前奏裁剪」。

## 文件

| 文件 | 作用 |
|---|---|
| `SOURCES.md` | 选句规则与源（先读） |
| `poetry.js` | 渲染引擎 |
| `film.js` | 入口：读作品的 `poem.json` |
| `defaults.json` | 固定观感与时间规则 |
| `compose.py` | work.json → poem.json（marks → pacing） |
| `retime.py` | 把已有 poem.json 的节奏改成固定规则（多行 2.3s/行、单行 0.4s/字） |
| `schema.json` | work.json 约束 |
| `build.skeleton.json` | 空白 work |
| `examples/zhuxian.work.json` | 金标准样例 |
| `examples/SHOWCASE.md` | 5 个已交付题材的实例索引（册数、场数、时长、路径） |
| `tools/weread_hot.py` | 查微信读书热门划线，按划线人数选中心句 |
| `build.json` | 旧版完整 poem 输入，保留兼容 |

`build.json` 是 2026-11-13 之前的写法：整份 `poem.json` 直接写在产线里。新作品请走 `work.json + --work`。
